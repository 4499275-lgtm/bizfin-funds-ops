# 规则中心与口径

## 一个规则平台，四个域

| 规则域 | 规则 | 策略（strategy） |
|---|---|---|
| ① 识别 | L1-001 支付公司清算款识别 | identify_payment_company（付款户名/摘要命中别名） |
| ① 识别 | L1-002 银行结息识别 | identify_nonbusiness（关键词；命中后走 L2-005 归属） |
| ① 识别 | L1-003 明确银行转账识别 | identify_transfer（订单号格式或用途关键词；**不是兜底**，未覆盖保持 UNIDENTIFIED） |
| ② 认领 | L2-001 支付公司 T+1 订单组认领 | 汇总认领：候选=支付成功+同支付公司+T+1 窗口+未被占用；理论到账=Σ(订单额−手续费)；与实际到账差 ≤ 容差才确认 |
| ② 认领 | L2-002 转账订单号聚合认领 | 摘要含订单号，多笔转账合计闭合订单 |
| ② 认领 | L2-003 转账客户汇总认领 | 付款方=客户名，子集和（minSize=2）闭合 |
| ② 认领 | L2-004 订单号明确的部分付款 | 唯一订单号且到账<订单剩余：整笔流水闭环，订单保留余额 |
| ② 认领 | L2-005 无应收资金类型归属 | 非业务入账自动归属 NRT-INTEREST；其余经人工确认（需凭据） |
| ③ 异常 | L3-001 清算金额差异 / L3-002 业务归属待确认 / L3-003 多候选·候选待确认 / L3-004 无候选 / L3-005 来源未识别 / L3-006 未闭环余额 / L3-007 手续费规则缺失 / L3-008 已认领订单变化冲突 | 只诊断、定位、路由；不修复数据、不创建认领 |

## 版本原则

- 规则/手续费发布即新版本（`POST /rules/:id/versions`），旧版本 `superseded_at`，不可原位修改；
- 执行按 `priority` 升序、启用、生效区间过滤；
- 输出对象记录命中规则的准确 id+version，`rule_hits` 按版本累计命中；
- 手续费/规则新版本**不改写已 CONFIRMED/FULL 的历史**：仅影响未闭环流水；Closed 流水在新数据影响下产生新版本但保留旧 Closed 历史。

## 固定业务口径（不可配置，来自产品基线）

- 单账户、单日收入流水；只处理收入（贷方），支出行仅留存原始行；
- T+1：周一银行入账匹配上周五/六/日支付成功订单，其他日匹配前一日；
- 订单只有支付公司维度，无支付渠道；订单不保存收款主体与预计结算周期；
- N:N 汇总认领仅在流水带显式清算组号（settlement_group_key）时成立，且按 GROUP_TOTAL 记账，不伪造逐笔对应；
- 人工确认结果不被自动重评估静默覆盖；异常关闭必须有依据。

## 手续费计算

```
理论到账 = Σ 订单金额 − Σ 手续费
手续费   = round(订单金额 × feeRateBps / 10000, 舍入模式) + fixedFeeCents
BATCH_TOTAL 时按清算组总额计费、按订单金额占比分摊（尾差归最后一笔）
```
